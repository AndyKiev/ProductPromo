# Переводы интерфейса и сообщений

Языки: English (`eng`, locale `en`) и Русский (`rus`, locale `ru`). Числовые ID
выдаёт БД; код не предполагает конкретных значений. Пользователь выбирает язык
через кнопку аккаунта справа вверху. Выбор сохраняется на сервере и действует
после перезагрузки и нового входа. До входа доступен отдельный выбор языка:
сохранённый выбор браузера, затем язык браузера, затем английский.

## Данные и API

- `langs`: `Id`, `ShortName`, `Name`, `Locale`.
- `msg_keys`: `Id`, `Name` (уникальный ключ), `Fallback`.
- `msgs`: `Id`, `MsgKeyId`, `LangId`, `Value`; уникальна пара ключ–язык.
- `user_preferences`: `Code` (JWT subject текущей авторизации), `LangId`.
  Отдельной постоянной таблицы пользователей у dev-auth пока нет.

Физические колонки PascalCase, атрибуты Python и поля API — snake_case.
Новые модели зарегистрированы в `backend/database/init_db.py`.

- `GET /api/v1/langs` — языки и их реальные ID; доступен до входа.
- `GET /api/v1/messages?lang_id=...` — `{lang_id, version, messages}`;
  один язык с разрешённым fallback, доступен до входа.
- `GET /api/v1/jwt/users/me` — профиль с `lang_id` и объектом `lang`.
- `PATCH /api/v1/jwt/users/me/language`, тело `{ "lang_id": ... }` — сохранить язык
  собственного аккаунта; требует JWT. Несуществующий ID отклоняется.
- `X-Lang-Id` — язык публичных сообщений, включая ошибку входа. Для доменных
  операций авторизованного пользователя приоритет у сохранённого профиля.
- Ответы мутаций и ошибки сохраняют `detail`, дополнительно содержат
  `message_key`, `params`, `lang_id`; ошибки валидации также содержат `errors`.

## Добавление переводов

Доменные `<domain>_messages.py` содержат ключ, английский `fallback` и начальный
`rus`. Ошибки и успехи импортируют эти константы. Параметры используют `${name}`;
набор параметров в двух языках должен совпадать. Подстановка выполняется один раз.

UI-каталог: `backend/backend/api_v1/msg/ui.json`. После изменения:

```powershell
node scripts/sync_i18n.mjs
make init-db
```

Синхронизация обновляет `frontend/src/i18n/ui.json`, резервный каталог SPA.
Старые feature `*Strings.ts` переэкспортируют его. В компонентах — `useString()`,
в DataGrid — `useDataGridLocale()`. Статические переводы MUI взяты из установленных
`@mui/x-data-grid` locales (MUI X, MIT); динамические подписи используют шаблоны
каталога, в том числе пагинация и количество выбранных строк.

`seed_translations()` создаёт отсутствующие языки, ключи и значения, сохраняя
редактирование переводчиков. Запускается при инициализации БД и старте приложения.
Изменение уже существующего текста в seed-файле не перезаписывает текст в БД:
для такой правки обновляют нужную строку `msgs` явно. Редактор переводов в UI в этот
этап не входит.

## Fallback и обновление

Перевод выбранного языка в БД → резервный текст выбранного языка в коде →
английский в БД → английский fallback → ключ. Бизнес-данные (например, названия
товаров и поставщиков) этим каталогом автоматически не переводятся.

Сервер кэширует снимок каталога на 30 секунд в каждом процессе. Чтение использует
отдельную сессию, поэтому ошибка транзакции CRUD не мешает показать сообщение.
При ошибке обновления остаётся последний успешный снимок. Фронтенд проверяет
каталог каждые 30 секунд в активной вкладке и при возврате к ней. Правки БД
появляются без сборки приложения, обычно в пределах 60 секунд.

Переключатель сначала загружает каталог и сохраняет профиль, затем меняет
интерфейс и обновляет запросы справочников. При неудаче язык остаётся прежним.

## Проверка

Из `backend/`: `poetry run python -m pytest tests/test_i18n.py -q`.
Из `frontend/`: `npm run typecheck`, затем `npm run build`.
Из `e2e/`: `npx playwright test tests/language.spec.ts --workers=1 --reporter=list`.
Браузерный тест временно меняет язык dev-аккаунта и создаёт тестовый рынок;
в конце восстанавливает язык и удаляет рынок. Запускать отдельно от тестов,
использующих тот же аккаунт.
