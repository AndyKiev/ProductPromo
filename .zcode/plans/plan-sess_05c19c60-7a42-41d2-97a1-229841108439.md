## Goal

1. Dropdown options for nomenclature essences show **`CODE Name`** (space-separated) everywhere these essences appear in selects — segments, categories, families (market and nomenclature key have no `code` column in the DB, so they stay name-only).
2. On `/admin/nomenclature/links` the filter selects (and the nomenclature create/edit dialog) become **type-to-searchable by code and by name** — like the family picker on key-links.
3. Key-links family picker: add `code` to option labels; its search already matches name+code server-side (`GET /nomenclature/families?q=` does `ILIKE` over `name, code`) — no backend change needed anywhere.

## Implementation (frontend only)

**New shared component** `frontend/src/components/admin/nomenclature/_shared/EntitySelect.tsx`
- MUI `Autocomplete` (client-side) over the full option list already loaded by the page: options `{ id, name, code? }`.
- Option/selected label: `code ? \`${code} ${name}\` : name`; exported helper `entityLabel(e)` reused by plain-dropdown pages.
- Custom `filterOptions`: case-insensitive, every whitespace-separated token must appear in `` `${code} ${name}` `` — so typing a code, a name fragment, or "code + name" together all work.
- Keeps current UX contract: `value` is numeric id with `0 = none`; a "none" option (label = existing `select…` placeholder) is shown when no query is typed; X-clear maps back to `0`; props for `label`, `disabled`, `error`, `helperText`, `sx` (same `minWidth: 200, flex: 1` sizing as today).

**Links page — filter bar** `nomenclature/NomenclatureKeySelector.tsx`
- Replace the private `CascadingSelect` (TextField select) with `EntitySelect` for all 7 selects: market/segment/category/family (code+name where code exists) and the 3 key-level selects (name-only labels, but now searchable by name). Option mappings pass the API objects' `code` through instead of dropping it.

**Links page — create/edit dialog** `nomenclature/NomenclatureForm.tsx`
- Convert the 4 cascading `TextField select` Controllers to `EntitySelect`, preserving zod error/helperText and the cascading reset of child fields.

**Key-links page** `nomenclature_key_link/KeyLinkTree.tsx`
- `searchFamilyOptions` label becomes `entityLabel(f)` (code + name). Server search untouched (already code+name).

**Label-only updates** (keep existing plain dropdowns, swap label to `entityLabel(...)`)
- `category/CategoryForm.tsx` (segment options), `family/FamilyForm.tsx` (category options), `products/product/ProductFilters.tsx` and `ProductForm.tsx` (segment/category/family options; market stays name). `SegmentForm` lists markets — no code exists, no change.

No backend or i18n changes (no new user-visible strings; labels reuse existing `getString` keys and the `selectPlaceholder`).
